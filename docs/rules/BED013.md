# BED013: Some columns are read as custom fields

| | |
|---|---|
| Name | `custom-columns` |
| Format | BED |
| Level | `info` |
| Source | BED v1.0 §4 |

A BED file has 3 to 12 standard fields, optionally followed by custom fields (written BED6+4 for six standard and four custom fields), and nothing inside the file says where the standard fields end. biolint reads the longest run of leading columns that fit the standard definitions on the first data line as standard and treats the rest as custom fields, which are not checked. ENCODE narrowPeak and broadPeak files come out as BED6+4 and BED6+3 this way, and a four-column bedGraph as BED4 (its value sits where a name would, and any text is a valid name). If the reading is not what you intended, the message names the value that stopped it; declare the layout with `--option bed.type=bed6+4` to override it.

## Example

A narrowPeak file: column 7 is a signal value, not thickStart:

```text
chr1→9356548→9356648→peak1→0→.→182.2→5.0945→-1→50
chr1→9358722→9358822→peak2→0→.→91.5→4.6052→-1→40
```

biolint reports:

```text
info[BED013]: 10 fields per line: read as BED6+4 (the ENCODE narrowPeak layout). Column 7 (`182.2`) does not fit thickStart (an integer between chromStart and chromEnd), so columns 7 to 10 are treated as custom fields and not checked
 --> example.bed:1:32
  |
1 | chr1→9356548→9356648→peak1→0→.→182.2→5.0945→-1→50
  |                                ^^^^^^^^^^^^^^^^^^
  = help: nothing to do if those columns hold data of your own; if column 7 is meant to be thickStart, this value is invalid. To declare the layout yourself use `--option bed.type=bed6+4`
  = spec: BED v1.0 §4
```

In these listings `→` stands for a tab.

## Accepted

```text
# peaks called on 2024-03-01
chr7→127471196→127472363→Pos1→0→+
chr7→127472363→127473530→Pos2→0→+
chr7→127475864→127477031→Neg1→0→-
```

## Configuration

Silence it with `--ignore BED013`, or check only this rule with `--select BED013`.
