# GTF201: Transcript has features on more than one sequence

| | |
|---|---|
| Name | `transcript-multiple-seqids` |
| Format | GTF |
| Level | `error` |
| Source | GTF 2.2, GTF Field Definitions: [attributes] (transcript_id) |

All features of one transcript lie on one sequence. When the same `transcript_id` appears on two, the file really contains two transcripts with one name: RSEM stops with "has exons on multiple chromosomes!", and tools that do not stop merge the two loci into one model. Known sources are UCSC table-browser exports of RefSeq, where one accession maps to several chromosomes or alternative haplotypes, and old GENCODE releases, which repeat the pseudoautosomal genes on chrX and chrY under the same identifiers. Make the identifiers unique, for example by adding a suffix on the second locus.

## Example

```text
chrX→example→exon→1200→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1";
chrY→example→exon→1200→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1";
```

biolint reports:

```text
error[GTF201]: transcript `g1.t1` is on `chrY` here, but its earlier features are on `chrX`
 --> example.gtf:2:1
  |
2 | chrY→example→exon→1200→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1";
  | ^^^^
  = help: two transcripts share this transcript_id: make the identifiers unique (for example with a suffix on the second locus), or remove the duplicate locus
  = note: the transcript first appears on line 1
  = spec: GTF 2.2, GTF Field Definitions: [attributes] (transcript_id)
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GTF201`, or check only this rule with `--select GTF201`.
