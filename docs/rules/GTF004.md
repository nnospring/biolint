# GTF004: Start or end is not a positive integer

| | |
|---|---|
| Name | `coordinate-invalid` |
| Format | GTF |
| Level | `error` |
| Source | GTF 2.2, GTF Field Definitions: <start> <end> |

Start and end are whole numbers counted from 1, and both ends are included. A 0 usually comes from BED, which counts starts from 0; `1e+05` and `1,000` are spreadsheet artefacts. Parsers stop at such a value or read it as something else.

## Example

A 0-based start:

```text
chr1→example→exon→0→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1";
```

biolint reports:

```text
error[GTF004]: start `0` is not a positive integer
 --> example.gtf:1:19
  |
1 | chr1→example→exon→0→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1";
  |                   ^
  = help: coordinates are 1-based: the first base of a sequence is 1. A 0 usually comes from converting BED (0-based starts) without adding 1
  = spec: GTF 2.2, GTF Field Definitions: <start> <end>
```

```text
chr1→example→exon→1200→1.35e+03→.→+→.→gene_id "g1"; transcript_id "g1.t1";
```

biolint reports:

```text
error[GTF004]: end `1.35e+03` is not a positive integer
 --> example.gtf:1:24
  |
1 | chr1→example→exon→1200→1.35e+03→.→+→.→gene_id "g1"; transcript_id "g1.t1";
  |                        ^^^^^^^^
  = help: scientific notation is usually a spreadsheet artefact; write the integer, e.g. `1350`
  = spec: GTF 2.2, GTF Field Definitions: <start> <end>
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GTF004`, or check only this rule with `--select GTF004`.
