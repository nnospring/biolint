# SAM119: SEQ uses letters that BAM cannot store

| | |
|---|---|
| Name | `seq-not-storable` |
| Format | SAM |
| Level | `warning` |
| Source | SAM v1 §4.2.3 |

SAM text allows any letter and `.` in SEQ, but BAM encodes only `=ACMGRSVTWYHKDBN`. samtools reads `U` as `T` and every other letter, and `.`, as `N`, without a message, so the sequence changes on conversion. Write RNA as `T` and unknown bases as `N`.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGUA→IIIII
```

biolint reports:

```text
warning[SAM119]: SEQ contains `U`, which BAM cannot store (samtools reads it as `T`)
 --> example.sam:3:29
  |
3 | r1→0→chr1→10→30→5M→*→0→0→ACGUA→IIIII
  |                             ^
  = help: write RNA bases as `T`
  = spec: SAM v1 §4.2.3
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM119`, or check only this rule with `--select SAM119`.
