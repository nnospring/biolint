# GTF103: No semicolon between two attributes

| | |
|---|---|
| Name | `semicolon-missing` |
| Format | GTF |
| Level | `error` |
| Source | GTF 2.2, GTF Field Definitions: [attributes] |

Every attribute ends with a semicolon. Without it the next key is read as part of the value, or the parser gives up: HTSeq stops with "The attribute string seems to contain mismatched quotes" or "Failure parsing GFF attribute line". The same symptom appears when a value itself contains a double quote, because the value then ends early.

## Example

```text
chr1→example→exon→1200→1350→.→+→.→gene_id "g1" transcript_id "g1.t1";
```

biolint reports:

```text
error[GTF103]: no semicolon after the value of `gene_id`
 --> example.gtf:1:46
  |
1 | chr1→example→exon→1200→1350→.→+→.→gene_id "g1" transcript_id "g1.t1";
  |                                              ^^^
  = help: end every attribute with a semicolon: `gene_id "g1"; transcript_id "t1";`. If the value contains spaces, put it in double quotes
  = spec: GTF 2.2, GTF Field Definitions: [attributes]
```

In these listings `→` stands for a tab.

## Accepted

```text
chr2→example→exon→1200→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1";
chr2→example→CDS→1299→1350→.→+→0→gene_id "g1"; transcript_id "g1.t1";
chr2→example→start_codon→1299→1301→.→+→0→gene_id "g1"; transcript_id "g1.t1";
chr2→example→exon→1500→1618→.→+→.→gene_id "g1"; transcript_id "g1.t1";
chr2→example→CDS→1500→1618→.→+→2→gene_id "g1"; transcript_id "g1.t1";
chr2→example→exon→1800→2100→.→+→.→gene_id "g1"; transcript_id "g1.t1";
chr2→example→CDS→1800→1898→.→+→0→gene_id "g1"; transcript_id "g1.t1";
chr2→example→stop_codon→1899→1901→.→+→0→gene_id "g1"; transcript_id "g1.t1";
```

## Configuration

Silence it with `--ignore GTF103`, or check only this rule with `--select GTF103`.
