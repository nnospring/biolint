# FQ001: Record does not start with @

| | |
|---|---|
| Name | `title-missing-at` |
| Format | FASTQ |
| Level | `error` |
| Source | Cock et al. 2010 (NAR 38:1767), "FASTQ definition" |

Every FASTQ record begins with a title line whose first character is `@`. Here a record was expected and the line starts with something else, so the four-line rhythm of the file is broken: a line was lost or added (often by an interrupted copy or a careless `head`/`split`), or the file is not FASTQ at all. Tools either stop here or read every following record wrongly. biolint reports the first such line and resumes at the next line that starts with `@`.

## Example

The title line of the second record is missing:

```text
@read1
ACGTACGT
+
IIIIIIII
ACGTACGT
+
IIIIIIII
```

biolint reports:

```text
error[FQ001]: expected a title line starting with `@` but found `ACGTACGT`
 --> example.fastq:5:1
  |
5 | ACGTACGT
  | ^
  = help: this looks like a sequence line whose `@title` line is missing
  = note: 1 record before this line were read without structural problems
  = spec: Cock et al. 2010 (NAR 38:1767), "FASTQ definition"
```

In these listings `→` stands for a tab.

## Accepted

```text
@SRR001666.1 071112_SLXA-EAS1_s_7:5:1:817:345 length=36
GGGTGATGGCCGCTGCCGATGGCGTCAAATCCCACC
+
IIIIIIIIIIIIIIIIIIIIIIIIIIIIII9IG9IC
@SRR001666.2 071112_SLXA-EAS1_s_7:5:1:801:338 length=36
GTTCAGGGATACGACGTTTGTATTTTAAGAATCTGA
+SRR001666.2 071112_SLXA-EAS1_s_7:5:1:801:338 length=36
IIIIIIIIIIIIIIIIIIIIIIIIIIIIIIII6IBI
```

## Configuration

Silence it with `--ignore FQ001`, or check only this rule with `--select FQ001`.
