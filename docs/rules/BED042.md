# BED042: Number of block sizes or starts differs from blockCount

| | |
|---|---|
| Name | `block-list-count` |
| Format | BED |
| Level | `error` |
| Source | BED v1.0 §1.9 |

blockSizes and blockStarts must each list exactly blockCount values. A mismatch means a list was truncated (long lists are a common victim of spreadsheet cell limits) or blockCount was not updated after editing. Parsers stop with an error, or read beyond the list.

## Example

```text
chr22→1000→5000→cloneA→960→+→1000→5000→0→3→567,488→0,3512
```

biolint reports:

```text
error[BED042]: blockSizes has 2 entries, but blockCount is `3`
 --> example.bed:1:44
  |
1 | chr22→1000→5000→cloneA→960→+→1000→5000→0→3→567,488→0,3512
  |                                            ^^^^^^^
  = help: blockSizes and blockStarts both have 2 entries: set blockCount to `2`
  = note: column 11 is read as blockSizes because the columns to its right on this line fit the standard fields that follow it; if column 11 is a custom field instead, declare it with `--option bed.type=bed9+3`
  = spec: BED v1.0 §1.9
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED042`, or check only this rule with `--select BED042`.
