# SAM022: Header value seems to contain the next field

| | |
|---|---|
| Name | `header-value-glued` |
| Format | SAM |
| Level | `warning` |
| Source | SAM v1 §1.3 |

A value such as `ID:rg1 SM:sample1` is legal as far as the pattern goes (values may contain spaces), but it almost certainly means a tab was typed or pasted as a space: tools take the whole text as the ID, so reads tagged `RG:Z:rg1` no longer match, and the sample name is lost. Some programs write their own `@PG` line this way. Only tags predefined for the record type are recognised after the space; `DS` and `CL` values are not examined.

## Example

The read group ID is read as "rg1 SM:sample1":

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
@RG→ID:rg1 SM:sample1
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM022]: the value `ID:rg1 SM:sample1` looks like two fields separated by a space instead of a tab
 --> example.sam:3:11
  |
3 | @RG→ID:rg1 SM:sample1
  |           ^
  = help: tools read the whole text as the value of `ID`; if `SM` was meant as its own field, put a tab before it
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Accepted

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
@RG→ID:rg1→SM:sample 1→DS:made with PL:ILLUMINA kit
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

## Configuration

Silence it with `--ignore SAM022`, or check only this rule with `--select SAM022`.
