# BED023: chromStart is greater than chromEnd

| | |
|---|---|
| Name | `start-after-end` |
| Format | BED |
| Level | `error` |
| Source | BED v1.0 §1.6 |

A feature runs from the smaller coordinate to the larger one, whatever its strand: the strand column says which way it points. Start may equal end (a zero-length feature such as an insertion point), but it may not exceed it. This happens when minus-strand features are written end first, or when 1-based coordinates are converted the wrong way round. BED counts from 0 and excludes the end: bases 1001 to 5000 in GFF or VCF numbering are written `1000 5000`.

## Example

```text
chr1→5000→1000
```

biolint reports:

```text
error[BED023]: chromStart `5000` is greater than chromEnd `1000`
 --> example.bed:1:6
  |
1 | chr1→5000→1000
  |      ^^^^^^^^^
  = help: write the smaller coordinate first (`1000\t5000`) and put the direction in the strand column. If the coordinates came from a 1-based format (GFF, VCF, a genome browser position), remember that BED counts from 0 and excludes the end: bases 1001–5000 are `1000\t5000`
  = spec: BED v1.0 §1.6
```

In these listings `→` stands for a tab.

## Accepted

```text
chr1→1000→1000
```

## Configuration

Silence it with `--ignore BED023`, or check only this rule with `--select BED023`.
