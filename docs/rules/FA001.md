# FA001: Sequence data before the first > header

| | |
|---|---|
| Name | `data-before-header` |
| Format | FASTA |
| Level | `error` |
| Source | NCBI BLAST help, FASTA; faidx(5) |

A FASTA file is a series of records, each starting with a description line that begins with `>`. Text before the first `>` belongs to no record: `samtools faidx` stops with "Format error, unexpected ...", and parsers that are more forgiving silently drop the lines. The usual causes are a header that lost its `>`, a file in another format (FASTQ, GenBank, Clustal) saved with a FASTA name, or the output of `grep -v ">"`.

## Example

The first record has no header line:

```text
ACGTACGTACGT
>seq2
ACGTACGTAAAA
```

biolint reports:

```text
error[FA001]: line `ACGTACGTACGT` comes before any `>` header
 --> example.fasta:1:1
  |
1 | ACGTACGTACGT
  | ^^^^^^^^^^^^
  = help: every record starts with a `>name` line; add one above this line
  = spec: NCBI BLAST help, FASTA; faidx(5)
```

In these listings `→` stands for a tab.

## Accepted

```text
>chr1 Homo sapiens test contig
ACGTACGTACGTNNNNacgtacgt
ACGTACGTACGTACGTACGTACGT
ACGTAC
>chr2
GGGCCCTTTAAA
```

## Configuration

Silence it with `--ignore FA001`, or check only this rule with `--select FA001`.
