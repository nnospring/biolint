# SAM020: Header line after the first alignment

| | |
|---|---|
| Name | `header-after-alignment` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1 |

All header lines come before the first alignment. samtools stops reading header lines at the first record, so a later `@` line is parsed as an alignment and fails. This is what `cat a.sam b.sam` produces: use `samtools merge` or `samtools cat` to join files.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
@SQ→SN:chr2→LN:900
r2→0→chr1→20→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM020]: `@SQ` header line after the alignments have started
 --> example.sam:4:1
  |
4 | @SQ→SN:chr2→LN:900
  | ^^^
  = help: move every header line above the first alignment; to join files use `samtools merge` or `samtools cat`, not `cat`
  = spec: SAM v1 §1
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM020`, or check only this rule with `--select SAM020`.
