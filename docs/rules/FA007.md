# FA007: Sequence lines of a record have different lengths

| | |
|---|---|
| Name | `line-length-uneven` |
| Format | FASTA |
| Level | `warning` |
| Source | faidx(5) |

Within one record every sequence line must have the same length, except the last, which may be shorter. Random access relies on this: `samtools faidx` refuses the file with "Different line length in sequence", and so does every tool that builds a `.fai` index through htslib. It happens after editing a sequence by hand or joining pieces with `cat`. Re-wrap with `seqkit seq -w 60 in.fa > out.fa`.

## Example

```text
>chr1
ACGTACGTACGT
ACGTACG
ACGTACGTACGT
```

biolint reports:

```text
warning[FA007]: line has 7 characters but the other lines of `chr1` have 12, and it is not the last line of the record
 --> example.fasta:3
  = help: re-wrap the file, e.g. `seqkit seq -w 60 in.fa > out.fa`; `samtools faidx` fails with "Different line length in sequence"
  = spec: faidx(5)
```

In these listings `→` stands for a tab.

## Accepted

```text
>chr1
ACGTACGTACGT
ACGTACGTACGT
ACGTACG
```

## Configuration

Silence it with `--ignore FA007`, or check only this rule with `--select FA007`.
