# SAM010: Reference name contains a forbidden character

| | |
|---|---|
| Name | `sq-name-invalid` |
| Format | SAM |
| Level | `warning` by default, `error` with `--strict` |
| Source | SAM v1 §1.2.1 |

Reference names are printable ASCII without spaces, backslashes, commas, quotation marks (single, double or backquote) or brackets `( ) [ ] { } < >`, and do not start with `*` or `=`. These characters are delimiters elsewhere (region strings, the `SA` tag, VCF), so a name containing them cannot be referred to unambiguously. The usual cause is a FASTA header whose description was kept as part of the name: align against a reference whose names stop at the first space.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1 Homo sapiens→LN:1000
r1→4→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM010]: reference name `chr1 Homo sapiens` contains a space
 --> example.sam:2:12
  |
2 | @SQ→SN:chr1 Homo sapiens→LN:1000
  |            ^
  = help: use the part before the first space (`chr1`): aligners take the reference name from the FASTA header up to the first whitespace
  = spec: SAM v1 §1.2.1
```

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:contig[1]→LN:1000
r1→4→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM010]: reference name `contig[1]` contains `[`
 --> example.sam:2:14
  |
2 | @SQ→SN:contig[1]→LN:1000
  |              ^
  = help: rename the sequence in the reference FASTA and realign, or rename it here and in every record with `samtools reheader`
  = spec: SAM v1 §1.2.1
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM010`, or check only this rule with `--select SAM010`.
