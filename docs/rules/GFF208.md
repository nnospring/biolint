# GFF208: Unescaped = or & inside an attribute value

| | |
|---|---|
| Name | `unescaped-character` |
| Format | GFF3 |
| Level | `off` by default, `error` with `--strict` |
| Source | GFF3 1.26, Description of the Format |

The characters `;`, `=`, `&` and `,` have a reserved meaning in column 9 and must be percent-encoded when they are part of a value (`=` as `%3D`, `&` as `%26`). Most parsers split each attribute at the first `=`, so the value survives and the default profile says nothing; GenomeTools rejects an attribute with more than one `=`.

## Example

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1;Note=pH=7 buffer
```

biolint reports:

```text
error[GFF208]: unescaped `=` in the value of `Note`
 --> example.gff3:2:51
  |
2 | chr1→example→gene→2100→7400→.→+→.→ID=gene1;Note=pH=7 buffer
  |                                                   ^
  = help: write it as `%3D`
  = spec: GFF3 1.26, Description of the Format
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GFF208`, or check only this rule with `--select GFF208`.
