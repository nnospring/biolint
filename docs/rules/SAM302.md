# SAM302: Header says SO:queryname but read names are not in order

| | |
|---|---|
| Name | `not-queryname-sorted` |
| Format | SAM |
| Level | `warning` |
| Source | SAM v1 §1.3 |

The specification does not fix one ordering for `SO:queryname`, only that it be applied consistently, and notes that libraries differ: `samtools sort -n` orders names "naturally" (`read9` before `read10`), while a plain character-by-character order puts `read10` first. This is reported when the names follow neither order (or not the one named by `SS:queryname:natural` or `SS:queryname:lexicographical`), so mates are probably not adjacent. Run `samtools sort -n`. Only the first out-of-order record is reported.

## Example

```text
@HD→VN:1.6→SO:queryname
@SQ→SN:chr1→LN:1000
readB→0→chr1→100→30→5M→*→0→0→ACGTA→IIIII
readA→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM302]: the header says `SO:queryname`, but `readA` comes after `readB`
 --> example.sam:4:1
  |
4 | readA→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
  | ^^^^^
  = help: sort the file by name (`samtools sort -n`), or correct the header to `SO:unsorted`
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Accepted

```text
@HD→VN:1.6→SO:queryname
@SQ→SN:chr1→LN:1000
read9→0→chr1→100→30→5M→*→0→0→ACGTA→IIIII
read10→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

## Configuration

Silence it with `--ignore SAM302`, or check only this rule with `--select SAM302`.
