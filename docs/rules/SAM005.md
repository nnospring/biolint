# SAM005: Header fields are separated by spaces instead of tabs

| | |
|---|---|
| Name | `header-spaces` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.3 |

Header fields are separated by single tab characters. Editors that expand tabs, and copying a header out of a terminal or a web page, replace them with spaces; the line then holds one long field, required tags such as `LN` are not found, and samtools refuses the header. When writing a read group on a command line, the tab is spelled `\t` inside quotes: `bwa mem -R '@RG\tID:x\tSM:y'`.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ SN:chr1 LN:1000
r1→4→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM005]: `@SQ` is followed by a space instead of a tab
 --> example.sam:2:4
  |
2 | @SQ SN:chr1 LN:1000
  |    ^
  = help: separate header fields with tab characters; if an editor converted them, switch off "expand tabs" and restore the file
  = spec: SAM v1 §1.3
```

One space is enough: LN is now part of the name:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1 LN:1000
r1→4→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM005]: a space separates `SN:chr1` from `LN:1000`, so the required `LN` field is not found
 --> example.sam:2:12
  |
2 | @SQ→SN:chr1 LN:1000
  |            ^
  = help: separate header fields with tab characters; on a command line write the tab as `\t` inside quotes
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM005`, or check only this rule with `--select SAM005`.
