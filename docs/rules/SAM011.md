# SAM011: @SQ LN is not a positive integer

| | |
|---|---|
| Name | `sq-length-invalid` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.3 |

`LN` is the reference length in bases: digits only, at least 1. samtools refuses 0, negative values and two different `LN` values on one line, and reads `LN:1,000` or `LN:1e6` as 1, so every later range check is wrong. Thousands separators and scientific notation come from spreadsheets.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:0
r1→4→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM011]: reference length `0` is not a positive integer
 --> example.sam:2:16
  |
2 | @SQ→SN:chr1→LN:0
  |                ^
  = help: a reference has at least one base; delete the @SQ line if the sequence is empty
  = spec: SAM v1 §1.3
```

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1,000
r1→4→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM011]: reference length `1,000` is not a positive integer
 --> example.sam:2:16
  |
2 | @SQ→SN:chr1→LN:1,000
  |                ^^^^^
  = help: write it without separators: `LN:1000`
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM011`, or check only this rule with `--select SAM011`.
