# SAM013: Two @SQ lines have the same SN

| | |
|---|---|
| Name | `sq-name-duplicate` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.3 |

Reference names must be unique, because alignment records refer to references by name. samtools stops with "Duplicate entry in sam header". The cause is nearly always two headers joined with `cat`; use `samtools merge` or `samtools reheader`.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM013]: reference `chr1` is already defined
 --> example.sam:3:8
  |
3 | @SQ→SN:chr1→LN:1000
  |        ^^^^
  = help: delete the repeated @SQ line; if two headers were joined with `cat`, use `samtools merge` instead
  = note: first defined on line 2
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM013`, or check only this rule with `--select SAM013`.
