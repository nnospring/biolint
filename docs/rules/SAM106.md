# SAM106: FLAG bits contradict each other or are reserved

| | |
|---|---|
| Name | `flag-inconsistent` |
| Format | SAM |
| Level | `warning` |
| Source | SAM v1 §1.4 |

Three combinations are reported, each resting on one item of the list that follows the FLAG table. (1) Bit 0x1 (paired) unset while 0x2, 0x8, 0x20, 0x40 or 0x80 is set. Basis: the item beginning "If 0x1 is unset", which says nothing may be assumed about those five bits, so they carry no information. (2) Bit 0x4 (unmapped) set together with 0x2, 0x100 or 0x800. Basis: the item on bit 0x4, whose second sentence says that when it is set nothing may be assumed about those three bits. (3) A bit above 0x800. Basis: the last item, which reserves unlisted bits and asks writers to leave them unset. The same items ask readers to ignore such bits rather than fail, so this is a warning in both profiles.

## Example

66 = 0x2 + 0x40 without 0x1:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→66→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM106]: FLAG 66 sets 0x2 proper pair + 0x40 first in template although the read is not marked as paired (0x1)
 --> example.sam:3:4
  |
3 | r1→66→chr1→10→30→5M→*→0→0→ACGTA→IIIII
  |    ^^
  = help: these bits only have a meaning for paired reads: use 67 if the read has a mate, or 0 if it does not
  = note: 66 = 0x2 proper pair + 0x40 first in template
  = spec: SAM v1 §1.4
```

260 = unmapped + secondary:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→260→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM106]: FLAG 260 marks the read as unmapped (0x4) and also sets 0x100 secondary
 --> example.sam:3:4
  |
3 | r1→260→*→0→0→*→*→0→0→ACGTA→IIIII
  |    ^^^
  = help: an unmapped read has no alignment to be proper, secondary or supplementary: use 4, or 256 if the read is in fact mapped
  = note: 260 = 0x4 unmapped + 0x100 secondary
  = spec: SAM v1 §1.4
```

Bit 0x1000 is not defined:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→4096→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM106]: FLAG 4096 sets bit 0x1000, which the specification reserves
 --> example.sam:3:4
  |
3 | r1→4096→chr1→10→30→5M→*→0→0→ACGTA→IIIII
  |    ^^^^
  = help: only 0x1 to 0x800 are defined, so a FLAG is at most 4095; without the reserved bits this one is 0
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM106`, or check only this rule with `--select SAM106`.
