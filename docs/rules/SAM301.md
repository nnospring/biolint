# SAM301: Header says SO:coordinate but records are out of order

| | |
|---|---|
| Name | `not-coordinate-sorted` |
| Format | SAM |
| Level | `warning` by default, `error` with `--strict` |
| Source | SAM v1 §1.3 |

A coordinate-sorted file lists records by reference, in the order of the `@SQ` lines, then by POS; records with RNAME `*` come last. `samtools index` stops with "Unsorted positions" on such a file once it is converted to BAM. The header was probably copied from a sorted file, or records were appended afterwards. Run `samtools sort`. Only the first out-of-order record is reported.

## Example

```text
@HD→VN:1.6→SO:coordinate
@SQ→SN:chr1→LN:1000
r1→0→chr1→100→30→5M→*→0→0→ACGTA→IIIII
r2→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM301]: the header says `SO:coordinate`, but `chr1`:10 comes after ``:100
 --> example.sam:4:11
  |
4 | r2→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
  |           ^^
  = help: sort the file (`samtools sort`), or correct the header to `SO:unsorted`; indexing a file in this state fails
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Accepted

```text
@HD→VN:1.6→SO:coordinate
@SQ→SN:chr1→LN:248956422
@RG→ID:rg1→SM:sample1→PL:ILLUMINA
@PG→ID:bwa→PN:bwa→VN:0.7.17
read1→99→chr1→100→60→10M→=→200→110→ACGTACGTAC→IIIIIIIIII→NM:i:0→RG:Z:rg1
read1→147→chr1→200→60→10M→=→100→-110→ACGTACGTAC→IIIIIIIIII→NM:i:0→RG:Z:rg1
```

## Configuration

Silence it with `--ignore SAM301`, or check only this rule with `--select SAM301`.
