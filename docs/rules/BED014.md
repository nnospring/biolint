# BED014: Block fields are incomplete (BED10 or BED11)

| | |
|---|---|
| Name | `blocks-incomplete` |
| Format | BED |
| Level | `warning` by default, `error` with `--strict` |
| Source | BED v1.0 §1.5 |

The three block fields (blockCount, blockSizes, blockStarts) only make sense together, so the specification prohibits files with 10 or 11 standard fields. This file has 10 or 11 columns and the last ones look like the beginning of a block description, as if the final columns were cut off. If those columns are custom fields of your own (BED9+1 or BED9+2), the file is fine and this can be ignored.

## Example

```text
chr22→1000→5000→cloneA→960→+→1000→5000→0→2
chr22→2000→6000→cloneB→900→-→2000→6000→0→2
```

biolint reports:

```text
warning[BED014]: 10 fields per line, and column 10 looks like a blockCount: BED10 is not allowed
 --> example.bed:1:42
  |
1 | chr22→1000→5000→cloneA→960→+→1000→5000→0→2
  |                                          ^
  = help: blockSizes and blockStarts are missing: add them to make BED12, or drop the block column to make BED9 (`cut -f1-9`). If these are custom columns of your own, declare that with `--option bed.type=bed9+1`
  = spec: BED v1.0 §1.5
```

In these listings `→` stands for a tab.

## Accepted

```text
chr22→1000→5000→cloneA→960→+→1000→5000→0→2→567,488,→0,3512
chr22→2000→6000→cloneB→900→-→2000→6000→0→2→433,399,→0,3601
```

## Configuration

Silence it with `--ignore BED014`, or check only this rule with `--select BED014`.
