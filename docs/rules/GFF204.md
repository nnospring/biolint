# GFF204: Same attribute tag twice on one line

| | |
|---|---|
| Name | `attribute-duplicate` |
| Format | GFF3 |
| Level | `warning` by default, `error` with `--strict` |
| Source | GFF3 1.26, Column 9: "attributes" |

Several values of one attribute are written once, separated by commas: `Parent=tx1,tx2`. When the tag is repeated instead, GenomeTools rejects the line, and a parser that keeps attributes in a dictionary (HTSeq, for one) retains only the last value.

## Example

```text
##gff-version 3
chr1→example→mRNA→2100→7400→.→+→.→ID=tx1
chr1→example→mRNA→2100→7400→.→+→.→ID=tx2
chr1→example→exon→2100→2600→.→+→.→Parent=tx1;Parent=tx2
```

biolint reports:

```text
warning[GFF204]: attribute `Parent` appears twice on this line
 --> example.gff3:4:46
  |
4 | chr1→example→exon→2100→2600→.→+→.→Parent=tx1;Parent=tx2
  |                                              ^^^^^^
  = help: write the values once, separated by commas: `Parent=value1,value2`
  = spec: GFF3 1.26, Column 9: "attributes"
```

In these listings `→` stands for a tab.

## Accepted

```text
##gff-version 3
chr1→example→mRNA→2100→7400→.→+→.→ID=tx1
chr1→example→mRNA→2100→7400→.→+→.→ID=tx2
chr1→example→exon→2100→2600→.→+→.→Parent=tx1,tx2
```

## Configuration

Silence it with `--ignore GFF204`, or check only this rule with `--select GFF204`.
