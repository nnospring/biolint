# FQ009: Quality scores use a legacy +64 encoding

| | |
|---|---|
| Name | `legacy-quality-encoding` |
| Format | FASTQ |
| Level | `warning` |
| Source | Cock et al. 2010 (NAR 38:1767), Table 1 |

The quality characters start at `;` or `@` and reach beyond `J`, which is the pattern of the Solexa and Illumina 1.3-1.7 variants (ASCII offset 64) rather than the standard Sanger encoding (offset 33) that every current tool expects. Read as offset 33, the scores are inflated by 31, so quality trimming and variant calling are silently wrong. Convert once, early in the pipeline. The variants cannot be told apart with certainty: biolint only reports when no character is below `;` and some are above `J`, and treats files of one constant quality character as standard.

## Example

```text
@HWUSI-EAS100R:6:73:941:1973#0/1
GATTTGGGGTTCAAAGCAGTATCGATCAAATAGTAAATCC
+
hhhhhhhhhhhghhhhhhhehhhedhhhhfhhhhhdggBB
```

biolint reports:

```text
warning[FQ009]: quality characters range from `B` (66) to `h` (104): this looks like an offset-64 encoding (Illumina 1.3-1.7, or Solexa), not the standard Phred+33
 --> example.fastq
  = help: if the data are Illumina 1.3-1.7, convert with `seqtk seq -Q64 -V in.fq > out.fq`; for Solexa scores use Biopython `SeqIO.convert("in.fq", "fastq-solexa", "out.fq", "fastq-sanger")`
  = note: no quality character is below `;` (59) and some are above `J` (74), which standard Phred+33 short-read data does not produce
  = spec: Cock et al. 2010 (NAR 38:1767), Table 1
```

In these listings `→` stands for a tab.

## Accepted

```text
@SRR001666.1 071112_SLXA-EAS1_s_7:5:1:817:345 length=36
GGGTGATGGCCGCTGCCGATGGCGTCAAATCCCACC
+
IIIIIIIIIIIIIIIIIIIIIIIIIIIIII9IG9IC
@SRR001666.2 071112_SLXA-EAS1_s_7:5:1:801:338 length=36
GTTCAGGGATACGACGTTTGTATTTTAAGAATCTGA
+SRR001666.2 071112_SLXA-EAS1_s_7:5:1:801:338 length=36
IIIIIIIIIIIIIIIIIIIIIIIIIIIIIIII6IBI
```

## Configuration

Silence it with `--ignore FQ009`, or check only this rule with `--select FQ009`.
