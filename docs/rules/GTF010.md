# GTF010: Comment at the end of a feature line

| | |
|---|---|
| Name | `inline-comment` |
| Format | GTF |
| Level | `warning` by default, `off` with `--strict` |
| Source | GTF 2.2, GTF Field Definitions: [comments] |

GTF 2.2 allows a `#` comment after the attributes of a feature line, so the strict profile accepts it. In practice parsers do not strip it (HTSeq and RSEM, for two, hand the whole rest of the line to their attribute parser), so the comment is read as one more attribute or as part of the last value. Keep comments on lines of their own.

## Example

```text
chr1→example→exon→1200→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1"; # first exon
```

biolint reports:

```text
warning[GTF010]: comment at the end of a feature line
 --> example.gtf:1:72
  |
1 | chr1→example→exon→1200→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1"; # first exon
  |                                                                        ^^^^^^^^^^^^
  = help: move the comment to a line of its own: most parsers do not strip it and read it as part of the attributes
  = spec: GTF 2.2, GTF Field Definitions: [comments]
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GTF010`, or check only this rule with `--select GTF010`.
