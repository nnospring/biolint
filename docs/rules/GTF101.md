# GTF101: Attributes are written in GFF3 style

| | |
|---|---|
| Name | `gff3-style-attributes` |
| Format | GTF |
| Level | `error` |
| Source | GTF 2.2, GTF Field Definitions: [attributes] |

This line writes its attributes as `ID=X;Parent=Y`, which is the GFF3 convention. GTF writes `gene_id "X"; transcript_id "Y";`. The first eight columns of the two formats look alike, but a GTF parser finds no `gene_id` in such a file: read counters report that no features were found. If the file is meant to be GFF3, rename it to `.gff3` (or check it with `--type gff3`); to get GTF, convert it with `gffread in.gff3 -T -o out.gtf` or `agat_convert_sp_gff2gtf.pl`.

## Example

```text
chr1→example→exon→1200→1350→.→+→.→ID=exon1;Parent=tx1
```

biolint reports:

```text
error[GTF101]: attribute `ID=exon1` is written in the GFF3 style, not as `key "value";`
 --> example.gtf:1:35
  |
1 | chr1→example→exon→1200→1350→.→+→.→ID=exon1;Parent=tx1
  |                                   ^^^^^^^^
  = help: the file is GFF3, not GTF: check it with `--type gff3`, or convert it with `gffread in.gff3 -T -o out.gtf`
  = spec: GTF 2.2, GTF Field Definitions: [attributes]
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GTF101`, or check only this rule with `--select GTF101`.
