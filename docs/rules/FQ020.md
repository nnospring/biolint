# FQ020: Paired reads are not complete pairs

| | |
|---|---|
| Name | `pair-count-mismatch` |
| Format | FASTQ |
| Level | `error` |
| Source | Cock et al. 2010 (NAR 38:1767), "FASTQ definition" (paired reads as two matched files) |

Paired-end data must contain both mates of every fragment, in the same order: either as two files with equal numbers of reads, or interleaved in one file as mate 1, mate 2, mate 1, ... Here the counts do not match (with `--paired`, the two files have different numbers of reads; in an interleaved file, the last read has no mate). One file was truncated, or the mates were filtered separately. Aligners stop ("paired reads have different names", "fewer reads in file") or, worse, pair the wrong reads. Re-pair with `seqkit pair -1 R1.fq -2 R2.fq` or BBMap `repair.sh`.

## Example

An interleaved file whose last read has no mate:

```text
@frag1/1
ACGTACGT
+
IIIIIIII
@frag1/2
TTGCATGC
+
IIIIIIII
@frag2/1
ACGTTTGT
+
IIIIIIII
```

biolint reports:

```text
error[FQ020]: the reads are interleaved pairs, but the file has 3 reads: the last read has no mate
 --> example.fastq:9
  = help: the file is truncated or a mate was filtered out; re-pair with `seqkit pair` or BBMap `repair.sh in=reads.fq out=fixed.fq outs=singletons.fq`
  = spec: Cock et al. 2010 (NAR 38:1767), "FASTQ definition" (paired reads as two matched files)
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FQ020`, or check only this rule with `--select FQ020`.
