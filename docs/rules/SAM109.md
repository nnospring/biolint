# SAM109: Mapped reads but no @SQ lines

| | |
|---|---|
| Name | `no-sq-header` |
| Format | SAM |
| Level | `error` by default, `warning` with `--strict` |
| Source | SAM v1 §2 |

The header is optional in the specification, which only recommends `@SQ` lines when reads are mapped. In practice samtools cannot read a mapped record without them ("no SQ lines present in the header"), because BAM stores references by number. The file was probably written without its header (`samtools view` without `-h`, `bowtie2 --no-hd`). Supply the reference when reading (`samtools view -t ref.fa.fai`) or regenerate the file with its header. Reported once per file.

## Example

```text
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM109]: records name a reference sequence, but the file has no header
 --> example.sam:1:6
  |
1 | r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
  |      ^^^^
  = help: samtools cannot read this file as it is: supply the reference index (`samtools view -t ref.fa.fai in.sam`), or write the file again with its header (`samtools view -h`)
  = spec: SAM v1 §2
```

In these listings `→` stands for a tab.

## Accepted

```text
r1→4→*→0→0→*→*→0→0→ACGTA→IIIII
```

## Configuration

Silence it with `--ignore SAM109`, or check only this rule with `--select SAM109`.
