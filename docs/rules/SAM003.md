# SAM003: Header field is not TAG:VALUE

| | |
|---|---|
| Name | `header-field-malformed` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.3 |

After the record type, every tab-separated field of a header line (except in `@CO`) is a two-character tag, a colon and a value, for example `SN:chr1`. A field without the colon in third position, an empty field (two tabs in a row, or a tab at the end of the line) or a line with no fields at all makes samtools stop with "Malformed key:value pair".

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000→hg38
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM003]: `hg38` is not a `TAG:VALUE` field
 --> example.sam:2:21
  |
2 | @SQ→SN:chr1→LN:1000→hg38
  |                     ^^^^
  = help: every field is a two-character tag, a colon and a value
  = spec: SAM v1 §1.3
```

A tab at the end of the line leaves an empty field:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000→
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM003]: the line ends with a tab, which leaves an empty field
 --> example.sam:2:20
  |
2 | @SQ→SN:chr1→LN:1000→
  |                    ^
  = help: remove the extra tab
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM003`, or check only this rule with `--select SAM003`.
