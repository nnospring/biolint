# SAM110: POS or PNEXT is not a non-negative integer

| | |
|---|---|
| Name | `pos-invalid` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.4 |

POS and PNEXT are 1-based positions written as whole numbers; 0 means "no position". Negative numbers, decimals, `*` and scientific notation (a spreadsheet artefact) make samtools stop with a parse error.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→-1→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM110]: POS `-1` is not a non-negative integer
 --> example.sam:3:11
  |
3 | r1→0→chr1→-1→30→5M→*→0→0→ACGTA→IIIII
  |           ^^
  = help: POS is 1-based and cannot be negative; write 0 when there is no position
  = spec: SAM v1 §1.4
```

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→*→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM110]: PNEXT `*` is not a non-negative integer
 --> example.sam:3:22
  |
3 | r1→0→chr1→10→30→5M→*→*→0→ACGTA→IIIII
  |                      ^
  = help: `*` is the placeholder of text fields; PNEXT is a number and its placeholder is `0`
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM110`, or check only this rule with `--select SAM110`.
