# VCF013: Reserved key declared with a different Number or Type

| | |
|---|---|
| Name | `meta-reserved-mismatch` |
| Format | VCF |
| Level | `warning` by default, `error` with `--strict` |
| Source | VCF 4.3 §1.6.1, §1.6.2 |

The specification fixes Number and Type for reserved keys such as `AC` (A, Integer), `AF` (A, Float), `DP` (1, Integer), `GT` (1, String), `AD` (R, Integer), `PL` (G, Integer). Tools rely on those definitions: `bcftools norm` splits multiallelic `AC`/`AF` per allele only when they are declared `Number=A`.

## Example

```text
##fileformat=VCFv4.3
##INFO=<ID=AF,Number=1,Type=Float,Description="Allele frequency">
#CHROM→POS→ID→REF→ALT→QUAL→FILTER→INFO
1→100→.→A→T→.→.→AF=0.5
```

biolint reports:

```text
warning[VCF013]: `AF` is a reserved INFO key defined as Number=A, Type=Float, but is declared Number=1, Type=Float
 --> example.vcf:2:22
  |
2 | ##INFO=<ID=AF,Number=1,Type=Float,Description="Allele frequency">
  |                      ^
  = help: declare it as `Number=A,Type=Float`, or use a different key name for this annotation
  = spec: VCF 4.3 §1.6.1, §1.6.2
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore VCF013`, or check only this rule with `--select VCF013`.
