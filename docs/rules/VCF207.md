# VCF207: Records of one CHROM are not in a single block

| | |
|---|---|
| Name | `chrom-not-contiguous` |
| Format | VCF |
| Level | `warning` by default, `error` with `--strict` |
| Source | VCF 4.3 §1.6.1 |

All records of a CHROM must be adjacent. A contig that reappears later breaks indexing and usually means the file was concatenated out of order. Sort with `bcftools sort`.

## Example

```text
##fileformat=VCFv4.3
#CHROM→POS→ID→REF→ALT→QUAL→FILTER→INFO
1→100→.→A→T→.→.→.
2→100→.→A→T→.→.→.
1→200→.→G→C→.→.→.
```

biolint reports:

```text
warning[VCF207]: records for `1` resume here after records of other contigs
 --> example.vcf:5:1
  |
5 | 1→200→.→G→C→.→.→.
  | ^
  = help: sort the file with `bcftools sort`
  = spec: VCF 4.3 §1.6.1
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore VCF207`, or check only this rule with `--select VCF207`.
