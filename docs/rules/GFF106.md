# GFF106: Start or end is not a positive integer

| | |
|---|---|
| Name | `coordinate-invalid` |
| Format | GFF3 |
| Level | `error` |
| Source | GFF3 1.26, Columns 4 & 5: "start" and "end" |

Start and end are whole numbers counted from 1: the first base of a sequence is 1, and both ends are included. A 0 usually comes from BED, which counts starts from 0; `1e+05` and `1,000` are spreadsheet artefacts. Parsers stop at such a value or read it as something else.

## Example

A 0-based start:

```text
##gff-version 3
chr1→example→gene→0→7400→.→+→.→ID=gene1
```

biolint reports:

```text
error[GFF106]: start `0` is not a positive integer
 --> example.gff3:2:19
  |
2 | chr1→example→gene→0→7400→.→+→.→ID=gene1
  |                   ^
  = help: coordinates are 1-based: the first base of a sequence is 1. A 0 usually comes from converting BED (0-based starts) without adding 1
  = spec: GFF3 1.26, Columns 4 & 5: "start" and "end"
```

```text
##gff-version 3
chr1→example→gene→2100→1e+05→.→+→.→ID=gene1
```

biolint reports:

```text
error[GFF106]: end `1e+05` is not a positive integer
 --> example.gff3:2:24
  |
2 | chr1→example→gene→2100→1e+05→.→+→.→ID=gene1
  |                        ^^^^^
  = help: scientific notation is usually a spreadsheet artefact; write the integer, e.g. `100000`
  = spec: GFF3 1.26, Columns 4 & 5: "start" and "end"
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GFF106`, or check only this rule with `--select GFF106`.
