# SAM118: SEQ contains a character that is not a base code

| | |
|---|---|
| Name | `seq-invalid` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.4 |

SEQ is `*` or a string of letters, `=` (same as the reference) and `.`. Digits, `-`, `*` inside a sequence and spaces are not bases. samtools does not stop: it stores an arbitrary base code instead (`AC1TA` is read back as `ACCTA`), so the sequence is silently changed. Gap characters come from aligned (padded) sequences pasted into SEQ; gaps belong in the CIGAR.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→AC-TA→IIIII
```

biolint reports:

```text
error[SAM118]: SEQ contains `-`, which is not a base code
 --> example.sam:3:28
  |
3 | r1→0→chr1→10→30→5M→*→0→0→AC-TA→IIIII
  |                            ^
  = help: gaps are not written in SEQ: remove the `-` characters and describe the gap in the CIGAR (`D` or `N`)
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM118`, or check only this rule with `--select SAM118`.
