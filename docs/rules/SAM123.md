# SAM123: Read is flagged as mapped but has no position or CIGAR

| | |
|---|---|
| Name | `mapped-incomplete` |
| Format | SAM |
| Level | `warning` |
| Source | SAM v1 §1.4 |

The unmapped bit (0x4) is not set, yet RNAME is `*`, POS is 0 or CIGAR is `*`. The specification allows this and only says that nothing may be assumed about the other fields; samtools treats the record as unmapped and says so ("treated as unmapped"), which changes its FLAG on conversion. Set flag bit 4 for reads that were not aligned.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM123]: FLAG 0 says the read is mapped, but CIGAR is `*`
 --> example.sam:3:4
  |
3 | r1→0→chr1→10→30→*→*→0→0→ACGTA→IIIII
  |    ^
  = help: samtools treats this record as unmapped; if it was not aligned, set the unmapped bit: FLAG 4
  = spec: SAM v1 §1.4
```

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→*→0→0→*→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
warning[SAM123]: FLAG 0 says the read is mapped, but RNAME is `*`
 --> example.sam:3:4
  |
3 | r1→0→*→0→0→*→*→0→0→ACGTA→IIIII
  |    ^
  = help: samtools treats this record as unmapped; if it was not aligned, set the unmapped bit: FLAG 4
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM123`, or check only this rule with `--select SAM123`.
