# FQ008: Sequence and quality are wrapped over several lines

| | |
|---|---|
| Name | `multi-line-record` |
| Format | FASTQ |
| Level | `warning` |
| Source | Cock et al. 2010 (NAR 38:1767), "FASTQ definition" |

The format allows the sequence and the quality string to be line-wrapped, but the authors recommend against it and nearly every current tool assumes exactly four lines per record. Because `@` and `+` are also valid quality characters, a wrapped file cannot be parsed line by line; four-line parsers read garbage or stop. Unwrap it with `seqtk seq -l0 in.fq > out.fq`.

## Example

```text
@read1
ACGTACGTAC
GTACGTAC
+
IIIIIIIIII
IIIIIIII
```

biolint reports:

```text
warning[FQ008]: the sequence of read `read1` continues on a second line (2 lines, 18 bases)
 --> example.fastq:3
  = help: most tools expect four lines per record; unwrap with `seqtk seq -l0 in.fq > out.fq`
  = spec: Cock et al. 2010 (NAR 38:1767), "FASTQ definition"
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FQ008`, or check only this rule with `--select FQ008`.
