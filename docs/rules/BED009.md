# BED009: Separators differ from the rest of the file

| | |
|---|---|
| Name | `mixed-separators` |
| Format | BED |
| Level | `error` by default, `warning` with `--strict` |
| Source | BED v1.0 §1.3, §3.5 |

The file separates fields with single tabs, but here a space, a space next to a tab, or two tabs in a row is used instead. Read to the letter, the specification allows any run of spaces and tabs (which is why this is only a warning in the strict profile), but tab-based tools take the stray space as part of the value: `chr1 ` is not chromosome `chr1`, and a line separated by spaces has one field. The result is a failure or, worse, features silently dropped. An editor replacing a tab with spaces on one edited line is the usual cause.

## Example

The second line uses spaces:

```text
chr1→1000→5000
chr1 7000 7250
```

biolint reports:

```text
error[BED009]: this line is separated by spaces; the lines before it (from line 1) use tabs
 --> example.bed:2:5
  |
2 | chr1 7000 7250
  |     ^
  = help: use exactly one tab between fields: `chr1\t7000\t7250`
  = fix: Separate the fields with single tabs (--fix)
  = spec: BED v1.0 §1.3, §3.5
```

A space before the tab:

```text
chr1→1000→5000
chr1 →7000→7250
```

biolint reports:

```text
error[BED009]: a space before the tab between fields 1 and 2
 --> example.bed:2:5
  |
2 | chr1 →7000→7250
  |     ^^
  = help: remove the space: tab-based tools take it as part of the value
  = fix: Remove the spaces next to tabs (--fix)
  = spec: BED v1.0 §1.3, §3.5
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED009`, or check only this rule with `--select BED009`.
