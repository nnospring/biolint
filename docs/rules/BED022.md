# BED022: chromStart or chromEnd is not a non-negative integer

| | |
|---|---|
| Name | `position-invalid` |
| Format | BED |
| Level | `error` |
| Source | BED v1.0 §1.6 |

Start and end are whole numbers written with digits only: no sign, no decimal point, no thousands separators, no exponent. The best-known offender is scientific notation: R writes 100000 as `1e+05` unless told otherwise (`options(scipen = 999)`), and spreadsheets do the same to large numbers. Negative starts appear when a flank is subtracted near the beginning of a chromosome. Parsers reject such lines or, worse, read `1e+05` as 1.

## Example

Scientific notation written by R or a spreadsheet:

```text
chr1→1e+05→200000
```

biolint reports:

```text
error[BED022]: chromStart `1e+05` is in scientific notation
 --> example.bed:1:6
  |
1 | chr1→1e+05→200000
  |      ^^^^^
  = help: write `100000`; R writes round numbers this way (`1e+05` for 100000): set `options(scipen = 999)` before `write.table`, or use `format(x, scientific = FALSE)`. Spreadsheets do the same to large numbers: format the column as a number without exponent
  = spec: BED v1.0 §1.6
```

Thousands separators:

```text
chr1→1,000→5,000
```

biolint reports:

```text
error[BED022]: chromStart `1,000` contains thousands separators
 --> example.bed:1:6
  |
1 | chr1→1,000→5,000
  |      ^^^^^
  = help: write `1000`: digits only
  = spec: BED v1.0 §1.6
```

Negative start:

```text
chr1→-50→450
```

biolint reports:

```text
error[BED022]: chromStart `-50` is negative
 --> example.bed:1:6
  |
1 | chr1→-50→450
  |      ^^^
  = help: BED coordinates start at 0. A negative value usually comes from subtracting a flank near the start of a chromosome: clamp it to `0` (`bedtools slop` and `bedtools flank` do this when given a genome file)
  = spec: BED v1.0 §1.6
```

Decimal:

```text
chr1→1000.5→5000
```

biolint reports:

```text
error[BED022]: chromStart `1000.5` is not a whole number
 --> example.bed:1:6
  |
1 | chr1→1000.5→5000
  |      ^^^^^^
  = help: positions are whole numbers of bases; round or truncate the value
  = spec: BED v1.0 §1.6
```

In these listings `→` stands for a tab.

## Accepted

```text
chr1→1000→5000
chr1→7000→7250
chr2→0→300
```

## Configuration

Silence it with `--ignore BED022`, or check only this rule with `--select BED022`.
