# FA012: > in the middle of a sequence line

| | |
|---|---|
| Name | `header-marker-in-sequence` |
| Format | FASTA |
| Level | `error` |
| Source | NCBI BLAST help, FASTA |

A `>` only starts a record at the beginning of a line. In the middle of a sequence line it means the newline before the next header is missing, typically because the previous file did not end with a newline when files were joined with `cat`. The next record is then swallowed into this one, header text and all.

## Example

```text
>seq1
ACGTACGTACGT>seq2
ACGTACGTAAAA
```

biolint reports:

```text
error[FA012]: `>` in the middle of a sequence line, before `seq2`
 --> example.fasta:2:13
  |
2 | ACGTACGTACGT>seq2
  |             ^
  = help: a line break is missing before `>`: the previous file probably did not end with a newline when files were concatenated
  = fix: Start a new line before > (--fix)
  = spec: NCBI BLAST help, FASTA
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FA012`, or check only this rule with `--select FA012`.
