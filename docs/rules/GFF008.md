# GFF008: Feature or directive after ##FASTA

| | |
|---|---|
| Name | `fasta-section-content` |
| Format | GFF3 |
| Level | `error` |
| Source | GFF3 1.26, Other Syntax: ##FASTA |

`##FASTA` ends the annotation part of the file: everything after it must be FASTA sequence, and all sequences must be together at the end. A parser that follows the specification stops reading features at `##FASTA`, so feature lines placed after it are lost without a message. This happens when annotation files that each embed their sequence (Prokka output, for example) are concatenated.

## Example

```text
##gff-version 3
ctgA→example→gene→3→20→.→+→.→ID=gene1
##FASTA
>ctgA
ACGTACGTACGTACGTACGTACGT
ctgA→example→gene→5→18→.→-→.→ID=gene2
```

biolint reports:

```text
error[GFF008]: a feature line after `##FASTA`
 --> example.gff3:6:1
  |
6 | ctgA→example→gene→5→18→.→-→.→ID=gene2
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = help: parsers stop reading features at `##FASTA`, so this line is ignored: move all features above it (several files were probably joined with `cat`)
  = note: the FASTA section starts on line 3
  = spec: GFF3 1.26, Other Syntax: ##FASTA
```

In these listings `→` stands for a tab.

## Accepted

```text
##gff-version 3.1.26
ctgA→example→gene→3→20→.→+→.→ID=gene1
##FASTA
>ctgA
ACGTACGTACGTACGTACGTACGT
```

## Configuration

Silence it with `--ignore GFF008`, or check only this rule with `--select GFF008`.
