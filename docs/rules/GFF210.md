# GFF210: Semicolon inside a quoted value splits the attribute

| | |
|---|---|
| Name | `quoted-value-split` |
| Format | GFF3 |
| Level | `warning` by default, `error` with `--strict` |
| Source | GFF3 1.26, Description of the Format |

Quotes do not protect anything in GFF3: a semicolon always ends an attribute. A value such as `note="binds ATP; essential"` is therefore cut after `ATP`, and the rest becomes a separate, meaningless attribute. Converters from GenBank or GTF that copy quoted text produce this. Write the semicolon as `%3B` and drop the quotes.

## Example

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1;note="binds ATP; essential"
```

biolint reports:

```text
warning[GFF210]: the semicolon inside the quoted value of `note` ends the attribute here
 --> example.gff3:2:59
  |
2 | chr1→example→gene→2100→7400→.→+→.→ID=gene1;note="binds ATP; essential"
  |                                                           ^
  = help: quotes do not protect a semicolon in GFF3: write it as `%3B` and remove the quotes
  = note: the value is cut to `"binds ATP`; `essential"` becomes a separate attribute
  = spec: GFF3 1.26, Description of the Format
```

In these listings `→` stands for a tab.

## Accepted

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1;note=binds ATP%3B essential
```

## Configuration

Silence it with `--ignore GFF210`, or check only this rule with `--select GFF210`.
