# BED008: Fields are separated by spaces, not tabs

| | |
|---|---|
| Name | `space-separated` |
| Format | BED |
| Level | `warning` |
| Source | BED v1.0 §1.3, §3.5 |

The specification accepts any run of spaces and tabs between fields, and the UCSC Genome Browser reads such files. Tools built around tab-separated text do not: bedtools documents that its input must be tab-delimited, tabix indexes tab-delimited files only, and table readers told to split on tabs see one column per line. The specification itself recommends a single tab. Space-separated files usually come from copying an example off a web page or from an editor that converts tabs to spaces.

## Example

```text
chr1 1000 5000
chr1 7000 7250
```

biolint reports:

```text
warning[BED008]: fields are separated by spaces, not tabs
 --> example.bed:1:5
  |
1 | chr1 1000 5000
  |     ^
  = help: convert to tabs if no value contains a space, e.g. `awk -v OFS="\t" '{$1=$1; print}' file.bed`; bedtools and tabix need tabs
  = spec: BED v1.0 §1.3, §3.5
```

In these listings `→` stands for a tab.

## Accepted

```text
chr1→1000→5000
chr1→7000→7250
chr2→0→300
```

## Configuration

Silence it with `--ignore BED008`, or check only this rule with `--select BED008`.
