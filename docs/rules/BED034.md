# BED034: Score is `.` instead of a number

| | |
|---|---|
| Name | `score-dot` |
| Format | BED |
| Level | `info` by default, `error` with `--strict` |
| Source | BED v1.0 §1.7 |

Many pipelines write `.` when there is no score. Tools that ignore the score accept that, but the specification asks for `0` when the score carries no information, and a parser that reads the score as a number fails on `.`.

## Example

```text
chr1→1000→5000→geneA→.→+
```

biolint reports:

```text
info[BED034]: score is `.`
 --> example.bed:1:22
  |
1 | chr1→1000→5000→geneA→.→+
  |                      ^
  = help: write `0` when there is no score
  = note: column 5 is read as score because the columns to its right on this line fit the standard fields that follow it; if column 5 is a custom field instead, declare it with `--option bed.type=bed4+2`
  = spec: BED v1.0 §1.7
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED034`, or check only this rule with `--select BED034`.
