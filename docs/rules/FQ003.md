# FQ003: Text after + differs from the title

| | |
|---|---|
| Name | `plus-line-mismatch` |
| Format | FASTQ |
| Level | `warning` by default, `error` with `--strict` |
| Source | Cock et al. 2010 (NAR 38:1767), "FASTQ definition" |

The `+` line may be bare, or it may repeat the title line exactly. Text that is different points to records that were shuffled or spliced together: the sequence and the qualities may belong to different reads. Most tools ignore the text after `+`, so the file still parses; `seqtk seq in.fq > out.fq` rewrites it with bare `+` lines.

## Example

```text
@read1
ACGTACGT
+read2
IIIIIIII
```

biolint reports:

```text
warning[FQ003]: the text after `+`, `read2`, differs from the title `read1` at character 6
 --> example.fastq:3:6
  |
3 | +read2
  |      ^
  = help: the sequence and quality may belong to different reads; if the file is otherwise sound, `seqtk seq in.fq > out.fq` rewrites it with bare `+` lines
  = note: title on line 1
  = spec: Cock et al. 2010 (NAR 38:1767), "FASTQ definition"
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FQ003`, or check only this rule with `--select FQ003`.
