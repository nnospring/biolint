# SAM015: Two @RG lines have the same ID

| | |
|---|---|
| Name | `rg-id-duplicate` |
| Format | SAM |
| Level | `warning` by default, `error` with `--strict` |
| Source | SAM v1 §1.3 |

Reads point at their read group through `RG:Z:<ID>`, so IDs must be unique. With duplicates samtools warns ("Duplicate entry") and it is no longer clear which sample or library a read belongs to. Joining headers by hand causes this; the specification expects merging tools to rename clashing IDs.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
@RG→ID:lane1→SM:sampleA
@RG→ID:lane1→SM:sampleB
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII→RG:Z:lane1
```

biolint reports:

```text
warning[SAM015]: read group `lane1` is already defined
 --> example.sam:4:8
  |
4 | @RG→ID:lane1→SM:sampleB
  |        ^^^^^
  = help: give each @RG line its own ID and update the `RG:Z:` tags of its reads (`samtools addreplacerg`), or delete the repeated line
  = note: first defined on line 3
  = spec: SAM v1 §1.3
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM015`, or check only this rule with `--select SAM015`.
