# GFF205: ID or Parent written in the wrong case

| | |
|---|---|
| Name | `reserved-tag-case` |
| Format | GFF3 |
| Level | `warning` |
| Source | GFF3 1.26, Column 9: "attributes" |

Attribute names are case-sensitive: `ID` and `Parent` have a defined meaning, `id` and `parent` are ordinary free-text attributes. A file that uses the lower-case spelling is syntactically valid, which is why nothing complains, but every parser sees features with no identifier and no parent, and the gene models fall apart into unrelated lines.

## Example

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→id=gene1
```

biolint reports:

```text
warning[GFF205]: attribute `id` is not the reserved tag `ID`: this feature has no identifier
 --> example.gff3:2:35
  |
2 | chr1→example→gene→2100→7400→.→+→.→id=gene1
  |                                   ^^
  = help: write `ID=` in upper case; tags are case-sensitive, so no parser treats `id` as the feature ID
  = spec: GFF3 1.26, Column 9: "attributes"
```

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1
chr1→example→mRNA→2100→7400→.→+→.→ID=tx1;parent=gene1
```

biolint reports:

```text
warning[GFF205]: attribute `parent` is not the reserved tag `Parent`: this feature is not linked to a parent
 --> example.gff3:3:42
  |
3 | chr1→example→mRNA→2100→7400→.→+→.→ID=tx1;parent=gene1
  |                                          ^^^^^^
  = help: write `Parent=` with a capital P; tags are case-sensitive, so no parser treats `parent` as the link to the parent feature
  = spec: GFF3 1.26, Column 9: "attributes"
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GFF205`, or check only this rule with `--select GFF205`.
