# SAM120: QUAL and SEQ have different lengths

| | |
|---|---|
| Name | `qual-length` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.4 |

QUAL holds one character per base of SEQ, or `*` when qualities are not stored; it cannot be given when SEQ is `*`. samtools stops with "SEQ and QUAL are of different length". Trimming one field and not the other, and truncated lines, cause this.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIII
```

biolint reports:

```text
error[SAM120]: QUAL has 4 characters but SEQ has 5 bases
 --> example.sam:3:32
  |
3 | r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIII
  |                                ^^^^
  = help: the two must be the same length: trim both fields together, or write `*` for QUAL; a mismatch on the last line means the file is truncated
  = spec: SAM v1 §1.4
```

Qualities without a sequence:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→*→IIIII
```

biolint reports:

```text
error[SAM120]: QUAL has 5 characters but SEQ is `*`
 --> example.sam:3:28
  |
3 | r1→0→chr1→10→30→5M→*→0→0→*→IIIII
  |                            ^^^^^
  = help: write `*` for QUAL when the sequence is not stored, or restore SEQ
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Accepted

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGTA→*
```

## Configuration

Silence it with `--ignore SAM120`, or check only this rule with `--select SAM120`.
