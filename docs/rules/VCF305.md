# VCF305: Number of INFO values does not match the declaration

| | |
|---|---|
| Name | `info-count` |
| Format | VCF |
| Level | `warning` by default, `error` with `--strict` |
| Source | VCF 4.3 §1.4.2 |

The header fixes how many comma-separated values a key carries: a number, `A` (one per ALT), `R` (one per allele) or `G` (one per genotype). The classic case is a multi-allelic record whose `AC`/`AF` were not split or merged along with the alleles.

## Example

```text
##fileformat=VCFv4.3
##INFO=<ID=AF,Number=A,Type=Float,Description="Allele frequency">
#CHROM→POS→ID→REF→ALT→QUAL→FILTER→INFO
1→100→.→A→T,G→.→.→AF=0.5
```

biolint reports:

```text
warning[VCF305]: `AF` has 1 value but its declaration requires one per ALT allele (2)
 --> example.vcf:4:22
  |
4 | 1→100→.→A→T,G→.→.→AF=0.5
  |                      ^^^
  = help: per-allele values must be updated whenever alleles are split, merged or removed (`bcftools norm` does this for declared tags)
  = note: declared as Number=A,Type=Float on line 2
  = spec: VCF 4.3 §1.4.2
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore VCF305`, or check only this rule with `--select VCF305`.
