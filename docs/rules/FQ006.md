# FQ006: Sequence character is not a nucleotide code

| | |
|---|---|
| Name | `sequence-invalid-character` |
| Format | FASTQ |
| Level | `warning` |
| Source | Cock et al. 2010 (NAR 38:1767), "FASTQ definition" |

The format sets no hard limit on sequence characters but recommends the IUPAC nucleotide codes (`A C G T U N` and the ambiguity codes `R Y K M S W B D H V`), in upper or lower case, plus `-` for a gap. Anything else is passed through by some tools and turned into `N` or rejected by others. A `.` is the "no call" of early Illumina pipelines (write `N`); digits after a leading base are SOLiD colour space, which is a different format.

## Example

`.` for an uncalled base:

```text
@read1
ACGT.CGT
+
IIIIIIII
```

biolint reports:

```text
warning[FQ006]: `.` in the sequence of read `read1` is not a nucleotide code
 --> example.fastq:2:5
  |
2 | ACGT.CGT
  |     ^
  = help: write an uncalled base as `N`; tools differ in what they do with `.`
  = spec: Cock et al. 2010 (NAR 38:1767), "FASTQ definition"
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FQ006`, or check only this rule with `--select FQ006`.
