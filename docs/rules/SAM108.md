# SAM108: Reference name is not declared in an @SQ line

| | |
|---|---|
| Name | `rname-unknown` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.4 |

When the header has `@SQ` lines, every RNAME and RNEXT (other than `*` and `=`) must be the `SN` of one of them. samtools warns "unrecognized reference name; treated as unmapped" and drops the position, so the read silently disappears from every region query. The usual cause is a header taken from a different reference build (`chr1` versus `1`), or names that keep the FASTA description.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM108]: RNAME `1` is not the `SN` of any @SQ line
 --> example.sam:3:6
  |
3 | r1→0→1→10→30→5M→*→0→0→ACGTA→IIIII
  |      ^
  = help: the header declares `chr1`: header and records use different naming (`chr` prefix), so they come from different reference files
  = spec: SAM v1 §1.4
```

The mate reference (RNEXT) is checked too:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→65→chr1→10→30→5M→chrM→20→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM108]: RNEXT `chrM` is not the `SN` of any @SQ line
 --> example.sam:3:21
  |
3 | r1→65→chr1→10→30→5M→chrM→20→0→ACGTA→IIIII
  |                     ^^^^
  = help: did you mean `chr1`? otherwise the header belongs to a different reference: rebuild it with `samtools view -T ref.fa`
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM108`, or check only this rule with `--select SAM108`.
