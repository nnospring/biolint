# SAM212: Optional field uses a BAM-only type letter

| | |
|---|---|
| Name | `aux-type-bam-only` |
| Format | SAM |
| Level | `warning` by default, `error` with `--strict` |
| Source | SAM v1 §1.5 |

`I` (unsigned 32-bit integer) and `d` (double) are type codes of the BAM encoding, not of SAM text, where integers are `i` and numbers are `f`. samtools reads `XX:I:5` as the integer 5 and keeps `XX:d:` values, so the file works there; parsers that follow the specification reject the record.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII→AS:I:50
```

biolint reports:

```text
warning[SAM212]: type `I` of `AS` is a BAM storage size, not a SAM type
 --> example.sam:3:41
  |
3 | r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII→AS:I:50
  |                                         ^
  = help: in SAM text every integer has type `i`: write `AS:i:50`
  = spec: SAM v1 §1.5
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM212`, or check only this rule with `--select SAM212`.
