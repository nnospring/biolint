# BED044: Last block does not end at chromEnd

| | |
|---|---|
| Name | `block-last-end` |
| Format | BED |
| Level | `error` |
| Source | BED v1.0 §1.9 |

The blocks must span the whole feature: the last block start plus the last block size must equal chromEnd − chromStart. If it does not, either chromEnd or the block lists were changed without the other, for example by trimming or extending the feature. Validating converters reject such lines, and anything that extracts the blocks (spliced sequence, exon coverage) works on the wrong bases.

## Example

```text
chr22→1000→5000→cloneA→960→+→1000→5000→0→2→567,400→0,3512
```

biolint reports:

```text
error[BED044]: the last block ends at offset `3912`, but the feature is `4000` long (chromEnd − chromStart)
 --> example.bed:1:48
  |
1 | chr22→1000→5000→cloneA→960→+→1000→5000→0→2→567,400→0,3512
  |                                                ^^^
  = help: the last block must end exactly at chromEnd: set chromEnd to `4912`, or the last block size to `488`
  = note: column 12 is read as blockStarts because the columns to its right on this line fit the standard fields that follow it; if column 12 is a custom field instead, declare it with `--option bed.type=bed9+3`
  = spec: BED v1.0 §1.9
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED044`, or check only this rule with `--select BED044`.
