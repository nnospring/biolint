# FA013: Letter is not a valid residue code for this kind of sequence

| | |
|---|---|
| Name | `invalid-residue` |
| Format | FASTA |
| Level | `error` |
| Source | IUPAC-IUB (NC-IUB 1984) nucleotide codes, as listed in NCBI BLAST help |

A nucleotide sequence may contain `A C G T U`, `N` and the ambiguity codes `R Y K M S W B D H V` (upper or lower case); `X` is tolerated because some maskers write it. Other letters are not bases, and tools that expect nucleotides replace them with `N` or a random base without saying so. They are typing or OCR errors, or protein sequence in a nucleotide file. biolint decides per file whether it holds nucleotides or protein and only reports letters when that is clear; say so explicitly with `-o fasta.alphabet=dna` (or `rna`, `protein`) if it guessed wrong.

## Example

`E` in a DNA sequence:

```text
>seq1
ACGTACGTACGTACGTACGTACGTACGTACGTAEGTACGTACGTACGT
```

biolint reports:

```text
error[FA013]: `E` is not a nucleotide code
 --> example.fasta:2:34
  |
2 | ACGTACGTACGTACGTACGTACGTACGTACGTAEGTACGTACGTACGT
  |                                  ^
  = help: nucleotide codes are A C G T U, N and the ambiguity codes R Y K M S W B D H V; replace an unknown base with `N` (if this is a protein file, pass `-o fasta.alphabet=protein`)
  = spec: IUPAC-IUB (NC-IUB 1984) nucleotide codes, as listed in NCBI BLAST help
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FA013`, or check only this rule with `--select FA013`.
