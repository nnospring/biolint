# GFF207: Comma in an attribute that takes a single value

| | |
|---|---|
| Name | `multiple-values-not-allowed` |
| Format | GFF3 |
| Level | `warning` by default, `error` with `--strict` |
| Source | GFF3 1.26, Column 9: "attributes" |

A comma separates several values, and among the defined tags only `Parent`, `Alias`, `Note`, `Dbxref` and `Ontology_term` may have more than one. A comma in an `ID`, `Name`, `Target`, `Gap`, `Derives_from` or `Is_circular` value is therefore read as two values. If the comma is part of the text, write it as `%2C`.

## Example

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1;Name=DNA polymerase III, alpha subunit
```

biolint reports:

```text
warning[GFF207]: `Name` takes a single value, but the comma makes this 2 values
 --> example.gff3:2:67
  |
2 | chr1→example→gene→2100→7400→.→+→.→ID=gene1;Name=DNA polymerase III, alpha subunit
  |                                                                   ^
  = help: if the comma is part of the text, write it as `%2C`
  = spec: GFF3 1.26, Column 9: "attributes"
```

In these listings `→` stands for a tab.

## Accepted

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1;Name=DNA polymerase III%2C alpha subunit
```

## Configuration

Silence it with `--ignore GFF207`, or check only this rule with `--select GFF207`.
