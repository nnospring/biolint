# GTF202: Transcript has features on both strands

| | |
|---|---|
| Name | `transcript-both-strands` |
| Format | GTF |
| Level | `error` |
| Source | GTF 2.2, GTF Field Definitions: [attributes] (transcript_id) |

A transcript is read from one strand, so all its exons have the same strand. Mixed strands mean either that two transcripts share a `transcript_id` or that the strand column of some lines is wrong. RSEM stops with "has exons from different orientations!" and GenomeTools refuses to convert the file. A transcript that is annotated across both strands on purpose (a trans-spliced gene such as mod(mdg4) in Drosophila) is reported as well, because the same tools fail on it; such transcripts are usually removed before quantification.

## Example

```text
chr1→example→exon→1200→1350→.→+→.→gene_id "g1"; transcript_id "g1.t1";
chr1→example→exon→1500→1618→.→-→.→gene_id "g1"; transcript_id "g1.t1";
```

biolint reports:

```text
error[GTF202]: transcript `g1.t1` is on the `-` strand here, but its earlier features are on `+`
 --> example.gtf:2:31
  |
2 | chr1→example→exon→1500→1618→.→-→.→gene_id "g1"; transcript_id "g1.t1";
  |                               ^
  = help: all features of a transcript share one strand: correct the strand column, or give the second transcript its own transcript_id (a genuinely trans-spliced transcript has to be removed or split for tools such as RSEM)
  = note: the transcript first appears on line 1
  = spec: GTF 2.2, GTF Field Definitions: [attributes] (transcript_id)
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GTF202`, or check only this rule with `--select GTF202`.
