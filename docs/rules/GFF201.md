# GFF201: Attribute is not tag=value

| | |
|---|---|
| Name | `attribute-malformed` |
| Format | GFF3 |
| Level | `error` |
| Source | GFF3 1.26, Column 9: "attributes" |

Column 9 is a list of `tag=value` pairs separated by semicolons. An entry without `=`, or without a tag before it, cannot be read. The usual cause is a semicolon inside a value (a description such as `kinase; putative`), which splits the value in two: write the semicolon as `%3B`.

## Example

A semicolon inside the Note splits it:

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1;Note=kinase; putative
```

biolint reports:

```text
error[GFF201]: attribute `putative` has no `=`
 --> example.gff3:2:57
  |
2 | chr1→example→gene→2100→7400→.→+→.→ID=gene1;Note=kinase; putative
  |                                                         ^^^^^^^^
  = help: if this text belongs to the value before it, the semicolon between them must be written `%3B`; otherwise write it as `tag=value`
  = spec: GFF3 1.26, Column 9: "attributes"
```

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1;=abcA
```

biolint reports:

```text
error[GFF201]: attribute `=abcA` has no tag before `=`
 --> example.gff3:2:44
  |
2 | chr1→example→gene→2100→7400→.→+→.→ID=gene1;=abcA
  |                                            ^^^^^
  = help: write it as `tag=value`, or write a literal `=` inside the previous value as `%3D`
  = spec: GFF3 1.26, Column 9: "attributes"
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GFF201`, or check only this rule with `--select GFF201`.
