# BED038: itemRgb is not `0` or three numbers from 0 to 255

| | |
|---|---|
| Name | `item-rgb` |
| Format | BED |
| Level | `warning` by default, `error` with `--strict` |
| Source | BED v1.0 §1.8 |

The colour is written as red, green and blue values from 0 to 255 separated by commas, without spaces: `255,0,0`. A single `0` means black; no other single number, colour name or hexadecimal code is valid. Tools that do not draw anything ignore the column, but genome browsers reject the line or fall back to black.

## Example

```text
chr1→1000→5000→geneA→0→+→1000→5000→255,0,0
chr1→7000→7250→geneB→0→-→7000→7250→#FF0000
```

biolint reports:

```text
warning[BED038]: itemRgb `#FF0000` is not `0` or three numbers from 0 to 255
 --> example.bed:2:36
  |
2 | chr1→7000→7250→geneB→0→-→7000→7250→#FF0000
  |                                    ^^^^^^^
  = help: write the colour as decimal R,G,B: `255,0,0`
  = note: 9 fields per line, all read as standard fields (BED9, inferred from line 1); if column 9 is a custom field instead, declare it with `--option bed.type=bed8+1`
  = spec: BED v1.0 §1.8
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED038`, or check only this rule with `--select BED038`.
