# BED011: Line has a different number of fields than the first data line

| | |
|---|---|
| Name | `field-count` |
| Format | BED |
| Level | `error` |
| Source | BED v1.0 §1.5 |

All data lines of a BED file must have the same number of fields. Parsers decide how to read the whole file from one line, so a short or long line is rejected or misread. Typical causes are a missing value (write `.` instead of leaving it out), a tab inside a name, or two files with different layouts joined with `cat`.

## Example

```text
chr1→1000→5000→geneA
chr1→7000→7250
```

biolint reports:

```text
error[BED011]: line has 3 fields, but line 1 has 4
 --> example.bed:2:1
  |
2 | chr1→7000→7250
  | ^^^^^^^^^^^^^^
  = help: a value is missing: write `.` (or `0` for a score) rather than leaving a field out; if two files with different layouts were joined, split them again
  = note: the first data line (line 1) sets the number of fields
  = spec: BED v1.0 §1.5
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED011`, or check only this rule with `--select BED011`.
