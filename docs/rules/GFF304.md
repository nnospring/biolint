# GFF304: Feature and its Parent are on different sequences

| | |
|---|---|
| Name | `parent-different-seqid` |
| Format | GFF3 |
| Level | `error` |
| Source | GFF3 1.26, Parent (part_of) Relationships |

`Parent` states that a feature is part of another one, and their coordinates are only comparable on the same sequence. An exon on `chr2` whose transcript is on `chr1` is rejected by GenomeTools and gives nonsense when a tool computes introns or extracts the spliced sequence. It nearly always means that IDs were reused across sequences (numbered per chromosome, say) and a child found the wrong parent.

## Example

```text
##gff-version 3
chr1→example→mRNA→2100→7400→.→+→.→ID=tx1
chr2→example→exon→2100→2600→.→+→.→Parent=tx1
```

biolint reports:

```text
error[GFF304]: Parent `tx1` is on `chr1`, but this feature is on `chr2`
 --> example.gff3:3:42
  |
3 | chr2→example→exon→2100→2600→.→+→.→Parent=tx1
  |                                          ^^^
  = help: a feature and its parent must be on the same sequence; IDs were probably reused across sequences
  = note: the parent is defined on line 2
  = spec: GFF3 1.26, Parent (part_of) Relationships
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GFF304`, or check only this rule with `--select GFF304`.
