# BED033: Score is not an integer from 0 to 1000

| | |
|---|---|
| Name | `score-invalid` |
| Format | BED |
| Level | `warning` by default, `error` with `--strict` |
| Source | BED v1.0 §1.7 |

The score is a whole number between 0 and 1000 that the Genome Browser turns into a shade of grey. Many programs put a p-value, a fold change or a read count there instead. Tools that ignore the score do not mind, but anything that follows the definition (the UCSC utilities, for one) may reject the file or draw it wrongly. Rescale the value into 0–1000, or write `0` and keep the real number in an extra column after the standard ones.

## Example

```text
chr1→1000→5000→peak1→12.5→+
```

biolint reports:

```text
warning[BED033]: score `12.5` is not a whole number
 --> example.bed:1:22
  |
1 | chr1→1000→5000→peak1→12.5→+
  |                      ^^^^
  = help: a score is an integer from 0 to 1000: round it, or write `0` and keep the real value (p-value, signal, fold change) in an extra column after the standard ones
  = note: column 5 is read as score because the columns to its right on this line fit the standard fields that follow it; if column 5 is a custom field instead, declare it with `--option bed.type=bed4+2`
  = spec: BED v1.0 §1.7
```

```text
chr1→1000→5000→peak1→4821→+
```

biolint reports:

```text
warning[BED033]: score `4821` is above 1000
 --> example.bed:1:22
  |
1 | chr1→1000→5000→peak1→4821→+
  |                      ^^^^
  = help: scores run from 0 to 1000: rescale, cap at `1000`, or write `0` and keep the real value in an extra column after the standard ones
  = note: column 5 is read as score because the columns to its right on this line fit the standard fields that follow it; if column 5 is a custom field instead, declare it with `--option bed.type=bed4+2`
  = spec: BED v1.0 §1.7
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED033`, or check only this rule with `--select BED033`.
