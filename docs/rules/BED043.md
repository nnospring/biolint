# BED043: First block does not start at chromStart

| | |
|---|---|
| Name | `block-first-start` |
| Format | BED |
| Level | `error` |
| Source | BED v1.0 §1.9 |

Block starts are offsets from chromStart, and the first block must begin exactly at chromStart, so the first value of blockStarts is always `0`. A first value equal to chromStart itself means absolute coordinates were written instead of offsets.

## Example

```text
chr22→1000→5000→cloneA→960→+→1000→5000→0→2→567,488→1000,4512
```

biolint reports:

```text
error[BED043]: the first block starts at offset `1000`, not at chromStart
 --> example.bed:1:52
  |
1 | chr22→1000→5000→cloneA→960→+→1000→5000→0→2→567,488→1000,4512
  |                                                    ^^^^
  = help: block starts are offsets from chromStart, not chromosome positions: subtract `1000` from every entry, so the list begins with `0`
  = note: column 12 is read as blockStarts because the columns to its right on this line fit the standard fields that follow it; if column 12 is a custom field instead, declare it with `--option bed.type=bed9+3`
  = spec: BED v1.0 §1.9
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED043`, or check only this rule with `--select BED043`.
