# SAM105: FLAG is not a decimal integer from 0 to 65535

| | |
|---|---|
| Name | `flag-invalid` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.4 |

FLAG is a whole number in decimal whose bits describe the read (paired, unmapped, reverse strand, ...). samtools refuses negative, non-numeric and too large values. It reads a leading zero as octal, so `016` becomes 14, and it accepts `0x10` although the field is defined as a decimal number: write plain decimal.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→65536→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM105]: FLAG 65536 is larger than 65535
 --> example.sam:3:4
  |
3 | r1→65536→chr1→10→30→5M→*→0→0→ACGTA→IIIII
  |    ^^^^^
  = help: only bits 0x1 to 0x800 are defined, so a valid FLAG is at most 4095: the column may hold something other than a flag
  = spec: SAM v1 §1.4
```

Read as octal 14 by samtools:

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→016→chr1→10→30→5M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM105]: FLAG `016` is not a decimal integer
 --> example.sam:3:4
  |
3 | r1→016→chr1→10→30→5M→*→0→0→ACGTA→IIIII
  |    ^^^
  = help: remove the leading zero: samtools reads a number that starts with 0 as octal (`016` becomes 14)
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM105`, or check only this rule with `--select SAM105`.
