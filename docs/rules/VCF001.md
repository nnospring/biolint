# VCF001: First line is not ##fileformat

| | |
|---|---|
| Name | `fileformat-missing` |
| Format | VCF |
| Level | `error` |
| Source | VCF 4.3 §1.4.1 |

Every VCF must begin with a `##fileformat=VCFv4.x` line. Parsers use it to pick the rules for everything that follows; htslib refuses or guesses when it is absent. It goes missing when headers are assembled by hand, when `grep -v "^#"` output is re-headered incompletely, or when a byte-order mark precedes it.

## Example

```text
##INFO=<ID=DP,Number=1,Type=Integer,Description="Total depth">
#CHROM→POS→ID→REF→ALT→QUAL→FILTER→INFO
1→100→.→A→T→.→.→DP=3
```

biolint reports:

```text
error[VCF001]: the first line must be `##fileformat=VCFv4.x`
 --> example.vcf:1:1
  |
1 | ##INFO=<ID=DP,Number=1,Type=Integer,Description="Total depth">
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = help: insert `##fileformat=VCFv4.2` (or the version the file follows) as the very first line
  = note: checking the rest of the file as VCF 4.2
  = spec: VCF 4.3 §1.4.1
```

In these listings `→` stands for a tab.

## Accepted

```text
##fileformat=VCFv4.3
##INFO=<ID=DP,Number=1,Type=Integer,Description="Total depth">
#CHROM→POS→ID→REF→ALT→QUAL→FILTER→INFO
1→100→.→A→T→.→.→DP=3
```

## Configuration

Silence it with `--ignore VCF001`, or check only this rule with `--select VCF001`.
