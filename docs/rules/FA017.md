# FA017: Too many sequences to check all identifiers for duplicates

| | |
|---|---|
| Name | `id-tracking-capped` |
| Format | FASTA |
| Level | `info` |

Finding duplicate identifiers means remembering every identifier seen. To keep memory bounded biolint stops remembering after a fixed number of records (one million by default, `-o fasta.maxIds=N` to change); later records are still compared with the remembered ones, but two late records that share an identifier are not detected. For a complete check use `seqkit rmdup -D dup.txt file.fa > /dev/null`, or `grep "^>" file.fa | cut -d" " -f1 | sort | uniq -d`.

## Example

The cap lowered to two identifiers to show the message:

With `-o fasta.maxIds=2`:

```text
>seq1
ACGT
>seq2
ACGT
>seq3
ACGT
```

biolint reports:

```text
info[FA017]: duplicate identifiers were checked against the first 2 records only (3 records in total)
 --> example.fasta
  = help: for a complete check run `seqkit rmdup -D dup.txt file.fa > /dev/null` and look at dup.txt
  = note: identifiers stopped being remembered at line 5
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FA017`, or check only this rule with `--select FA017`.
