# SAM116: CIGAR and SEQ describe different read lengths

| | |
|---|---|
| Name | `cigar-seq-length` |
| Format | SAM |
| Level | `error` |
| Source | SAM v1 §1.4 |

The lengths of the `M`, `I`, `S`, `=` and `X` operations add up to the number of bases in SEQ (when SEQ is not `*`). `D`, `N`, `H` and `P` do not count. samtools stops with "CIGAR and query sequence are of different length". Typical causes: SEQ was trimmed after alignment, hard-clipped bases were left in SEQ, or the line was truncated.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→6M→*→0→0→ACGTA→IIIII
```

biolint reports:

```text
error[SAM116]: CIGAR `6M` describes 6 read bases but SEQ has 5
 --> example.sam:3:17
  |
3 | r1→0→chr1→10→30→6M→*→0→0→ACGTA→IIIII
  |                 ^^
  = help: the lengths of M, I, S, = and X must add up to the length of SEQ: if bases were trimmed after alignment, the CIGAR must be trimmed too; hard-clipped (H) bases are not part of SEQ
  = spec: SAM v1 §1.4
```

In these listings `→` stands for a tab.

## Accepted

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→2M3D1I2M→*→0→0→ACGTA→IIIII
```

## Configuration

Silence it with `--ignore SAM116`, or check only this rule with `--select SAM116`.
