# BED040: blockCount is not a positive integer

| | |
|---|---|
| Name | `block-count` |
| Format | BED |
| Level | `error` |
| Source | BED v1.0 §1.9 |

blockCount is the number of blocks (exons) and must be at least 1: a feature without sub-structure has one block covering all of it (`1`, its length, `0`). The field table of the specification gives the range as starting at 0, but its text says "greater than 0", and a feature with no blocks cannot satisfy the rule that blocks start at chromStart and end at chromEnd.

## Example

```text
chr22→1000→5000→cloneA→960→+→1000→5000→0→0→567,488→0,3512
```

biolint reports:

```text
error[BED040]: blockCount is `0`
 --> example.bed:1:42
  |
1 | chr22→1000→5000→cloneA→960→+→1000→5000→0→0→567,488→0,3512
  |                                          ^
  = help: a feature has at least one block; for a feature without sub-structure write `1\t4000\t0`
  = note: column 10 is read as blockCount because the columns to its right on this line fit the standard fields that follow it; if column 10 is a custom field instead, declare it with `--option bed.type=bed9+3`
  = spec: BED v1.0 §1.9
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore BED040`, or check only this rule with `--select BED040`.
