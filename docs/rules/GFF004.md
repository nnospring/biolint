# GFF004: ##gff-version appears more than once

| | |
|---|---|
| Name | `version-repeated` |
| Format | GFF3 |
| Level | `warning` by default, `error` with `--strict` |
| Source | GFF3 1.26, Change Log 1.21 |

A second `##gff-version` line almost always means that two GFF3 files were joined with `cat`. The joined file may then contain the same ID twice and `##sequence-region` lines in the middle of the features. Merge annotation files with a tool that understands the format, such as `gt gff3 -sort` or `agat_sp_merge_annotations.pl`.

## Example

```text
##gff-version 3
chr1→example→gene→2100→7400→.→+→.→ID=gene1
##gff-version 3
chr2→example→gene→500→800→.→-→.→ID=gene2
```

biolint reports:

```text
warning[GFF004]: `##gff-version` appears again
 --> example.gff3:3:1
  |
3 | ##gff-version 3
  | ^^^^^^^^^^^^^^^
  = help: if two GFF3 files were joined with `cat`, merge them with `gt gff3 -sort a.gff3 b.gff3` or AGAT instead, and keep one header
  = note: first seen on line 1
  = spec: GFF3 1.26, Change Log 1.21
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GFF004`, or check only this rule with `--select GFF004`.
