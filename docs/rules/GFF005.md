# GFF005: ##sequence-region is not "seqid start end"

| | |
|---|---|
| Name | `sequence-region-invalid` |
| Format | GFF3 |
| Level | `error` |
| Source | GFF3 1.26, Other Syntax: ##sequence-region |

The directive names a sequence and its extent: `##sequence-region chr1 1 248956422`. Start and end are positive integers with start not after end. Parsers use it for bounds checking and genome browsers use it to size the sequence, so a malformed line is either rejected or silently ignored.

## Example

```text
##gff-version 3
##sequence-region chr1 50000
chr1→example→gene→2100→7400→.→+→.→ID=gene1
```

biolint reports:

```text
error[GFF005]: `##sequence-region` has 2 values, expected a sequence name, a start and an end
 --> example.gff3:2:1
  |
2 | ##sequence-region chr1 50000
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = help: give both ends of the sequence, e.g. `##sequence-region chr1 1 248956422`
  = spec: GFF3 1.26, Other Syntax: ##sequence-region
```

Start and end are swapped:

```text
##gff-version 3
##sequence-region chr1 50000 1
chr1→example→gene→2100→7400→.→+→.→ID=gene1
```

biolint reports:

```text
error[GFF005]: `##sequence-region` start 50000 is greater than end 1
 --> example.gff3:2:1
  |
2 | ##sequence-region chr1 50000 1
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = help: write the smaller number first: `##sequence-region chr1 1 50000`
  = spec: GFF3 1.26, Other Syntax: ##sequence-region
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore GFF005`, or check only this rule with `--select GFF005`.
