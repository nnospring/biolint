# SAM206: Optional field value is outside the pattern for its type

| | |
|---|---|
| Name | `aux-value-nonstandard` |
| Format | SAM |
| Level | `warning` by default, `error` with `--strict` |
| Source | SAM v1 §1.5 |

The value can be read, and samtools keeps it, but it is not what the specification allows for the type: `nan`, `inf` or `5.` for `f` (the pattern needs digits after the point); a number too large for single precision; lower-case digits in `H`; a space or non-ASCII character in `A`, or non-ASCII in `Z`; a `B` element outside the range of its element type (samtools changes the element type to fit). A parser that applies the specification's patterns rejects these.

## Example

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII→XF:f:nan
```

biolint reports:

```text
warning[SAM206]: `nan` is not a number the specification's `f` pattern allows
 --> example.sam:3:43
  |
3 | r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII→XF:f:nan
  |                                           ^^^
  = help: samtools reads and writes `nan` and `inf`, but the pattern for `f` has digits only: leave the field out when the value is undefined
  = spec: SAM v1 §1.5
```

```text
@HD→VN:1.6→SO:unsorted
@SQ→SN:chr1→LN:1000
r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII→XB:B:C,256
```

biolint reports:

```text
warning[SAM206]: array element 256 is outside the range of element type `C` (0 to 255)
 --> example.sam:3:45
  |
3 | r1→0→chr1→10→30→5M→*→0→0→ACGTA→IIIII→XB:B:C,256
  |                                             ^^^
  = help: declare a wider element type, e.g. `XB:B:i,...`; samtools silently changes the type to make the values fit
  = spec: SAM v1 §1.5
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore SAM206`, or check only this rule with `--select SAM206`.
