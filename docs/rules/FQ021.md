# FQ021: Mates of a pair have different read names

| | |
|---|---|
| Name | `pair-name-mismatch` |
| Format | FASTQ |
| Level | `error` |
| Source | Cock et al. 2010 (NAR 38:1767), "FASTQ definition" (paired reads as two matched files) |

The two mates of a fragment carry the same read name (apart from a trailing `/1` or `/2`, or the comment after the first space). Names that differ at the same position mean the files are out of step: one was sorted, filtered or trimmed without the other, or a read was lost. Everything after that point is paired with the wrong mate. With `--paired`, biolint compares a running digest of the names and reports the block of 4,096 reads in which the two files first differ. Re-pair with `seqkit pair -1 R1.fq -2 R2.fq` or BBMap `repair.sh`.

## Example

An interleaved file in which the fourth read is not the mate of the third:

```text
@frag1/1
ACGTACGT
+
IIIIIIII
@frag1/2
TTGCATGC
+
IIIIIIII
@frag2/1
ACGTTTGT
+
IIIIIIII
@frag3/2
GGGTTTGT
+
IIIIIIII
```

biolint reports:

```text
error[FQ021]: read 4 is named read `frag3/2` but its mate, the read before it, has a different name
  --> example.fastq:13:2
   |
13 | @frag3/2
   |  ^^^^^
   = help: the file is interleaved (reads 1 and 2 are the two mates of one fragment), so reads must alternate mate 1, mate 2; a read was lost or the mates were filtered separately. Re-pair with BBMap `repair.sh in=reads.fq out=fixed.fq outs=singletons.fq`
   = note: previous read on line 9
   = spec: Cock et al. 2010 (NAR 38:1767), "FASTQ definition" (paired reads as two matched files)
```

In these listings `→` stands for a tab.

## Configuration

Silence it with `--ignore FQ021`, or check only this rule with `--select FQ021`.
